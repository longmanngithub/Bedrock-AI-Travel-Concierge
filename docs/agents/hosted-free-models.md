Checked November 23, 2026. These options cover model inference for the seven-agent CrewAI travel planner. Provider capabilities and quotas come from documentation. The setup below records the mixed profile exercised locally.

Cloudflare bills the daily allocation by model and token direction. A hypothetical trip totaling 60,000 input and 10,000 output tokens across calls uses about 694 Neurons on GLM-4.7-Flash or 2,591 on GPT-OSS 120B. At those illustrative token counts, the allowance covers about 14 or 3 whole trips per day, respectively, before additional traffic. Measure actual usage because the tool loop, reasoning, and retry counts depend on the trip. [Per-model Neuron rates](https://developers.cloudflare.com/workers-ai/platform/pricing/).

## Configure and verify the mixed profile

1. Use the mixed profile in [the backend environment template](../../backend/.env.example). Set `MODEL` to Groq GPT-OSS 120B and supply `GROQ_API_KEY` for chat.
2. Create a scoped Cloudflare Workers AI token and set `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_KEY`. The profile assigns GLM-4.7-Flash to research and planning, and GPT-OSS 120B to review. Set `CLOUDFLARE_CREW_MAX_RPM=30` to try the documented crew limit. Restart the API and worker together. [Cloudflare token setup](https://developers.cloudflare.com/workers-ai/get-started/rest-api/).
3. Run a trip through chat and check the completed itinerary, budget, citation links, and conversation reload. The Cloudflare reviewer validates the `Itinerary` schema and shares a 120-second default deadline across two attempts. The frontend paces the display of incoming reply chunks and honors reduced motion.

The local five-day Bangkok smoke test completed in 4m 26s with travel tools
enabled and returned 62 sources. This is a single observed run. Provider load,
tool latency, and trip size affect timing.
